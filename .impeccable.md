# Confirmed Design Context

Updated 16 November 2026. This decision supersedes the initial warm-neutral/deep-teal visual direction and the brief intermediate Editorial selection.

## Users and purpose

B2B software support Agents and Admins work through conversations, inspect evidence, draft replies and approve consequential actions. Viewers inspect without changing state. Customers communicate through email and never enter this workspace.

## Approved direction: Command Bright (D)

The user selected the Command layout (C), requested brighter colors and stronger contrast, then accepted the resulting D prototype. Use D as the production design reference; do not reopen the A/B/C direction interview.

Personality remains calm, precise and capable. Express it through a modern operations workspace: compact left navigation, a clear ticket table above the selected conversation, and adjacent evidence/context when screen width allows. Use brighter slate surfaces, near-white text, readable secondary text, distinct borders and vivid lime actions. Supporting labels are larger than the original Command prototype. Avoid chatbot styling, decorative metric cards, fabricated claims and visual-only production controls.

Reference: docs/prototypes/command-bright.png and the D overrides in apps/web/app/inbox/prototype/directions.css on feat/ui-direction-prototypes (prototype commit 7899634).

Dark theme baseline: canvas #202832; surface #2A3440; text #F4F7FB; secondary #C3CEDA; border #687889; primary #C3EF87; on-primary #203215; selected background #354B39. These are a starting point for organized primitive/semantic/component tokens, not permission to scatter values through components.

Keep the licensed Manrope / Source Sans 3 pairing unless a concrete legibility issue justifies a change. Retain light-theme support, designed as a complementary version of this direction; the light palette is not yet validated. Target WCAG 2.2 AA, keyboard access, reduced motion, native 200% zoom and mobile task completion.

The prototype is illustrative and has simulated data/actions, a placeholder icon, and incomplete accessibility behavior. Rewrite the accepted visual design around actual persisted/API behavior. Never promote the throwaway switcher or simulated drafting, sources or approval into the production flow. Complete the original custom brand assets and usage guide in the planned branding work.
